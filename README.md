# vbm-orchestrator

**The task cycle as a pure state machine.** One task goes through its cycle: prepare a workspace, run a worker agent, validate the change with the lander's checks, have it reviewed, land it, and clean up. A failed check, a conflict or a reviewer's finding goes back to the SAME worker session, whole, after a decision model has judged that the task is still converging; the only hard stops are a money ceiling (a fuse) and a wall deadline. Written once in Lean 4 and machine-checked: the worker runs at most as often as the money allows, a task reports at most once, lands only a done outcome after the lander validated it and the reviewers cleared it, never approves through an unreachable reviewer, and cleans up exactly once on every path. And no text payload decides what it does: two runs over events that differ only in their words ask for the same actions and end in the same phase.

> **Status: pre-release.** The specification and its first proofs. Nothing is published to a package registry.

## What it is, and what it is not

A specification, its proofs, a reference model (the machine driven under the port discipline) and conformance vectors (`vectors/`, format in `docs/vectors.md`): language-neutral scenarios that any interpreter runs in its own tests. `step : Config → State → Event → State × List Action` is total and pure: it has no input or output, no clock, no model and no storage. An interpreter turns each action into a call of a port (the workspace, the agent, the lander, the reviewers, the judge) and each answer into the next event. It depends on [vbm-work](https://github.com/witt3rd/vbm-work) for the words it shares (the task, the typed outcome, the review verdict) and on nothing else.

## Build and test

Prerequisites: `git`, [mise](https://mise.jdx.dev). `mise exec -- scripts/tier1.sh` is the gate (Lean 4.35.0, pinned in `mise.toml`). The claims and the theorems that prove them are in `docs/proof-ledger.md`, generated by the gate.

## How it is built

Agents write it under mechanical gates instead of line-by-line review, to the [VBM standard](https://github.com/witt3rd/vbm). It lands directly on `main` with `.land/land-direct`, a pinned copy of [vbm-land](https://github.com/witt3rd/vbm-land).
